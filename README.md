# Campus Evacuation Planning with LLM Agents and DRQN



A campus evacuation simulation system that combines LLM-based human behavior modeling, LLM-driven zone coordination, and Deep Recurrent Q-Network (DRQN) navigation on a real OSM graph of the University of Utah campus.

---

## System Architecture

The system is designed as a three-layer pipeline, where each layer handles a different aspect of the evacuation problem:

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: LLM Human Behavior Profiler                        │
│  - Input: natural language persona descriptions              │
│  - Output: quantitative behavior parameters per agent        │
│  - Model: Llama 3.3 70B (Groq)                               │
│  - File: llm_behavior_profiler.py                            │
└──────────────────────────┬──────────────────────────────────┘
                           │ agent_profiles.json
┌──────────────────────────▼──────────────────────────────────┐
│  Layer 2: LLM Zone Coordinator Agent  (planned)              │
│  - Tool-using LLM (ReAct loop)                               │
│  - Tools: shelter status, zone population, road conditions   │
│  - Output: zone-to-shelter assignment                        │
│  - File: llm_zone_coordinator.py                             │
└──────────────────────────┬──────────────────────────────────┘
                           │ zone assignments
┌──────────────────────────▼──────────────────────────────────┐
│  Layer 3: DRQN Navigation                                     │
│  - Graph-based POMDP on OSM walk/drive network               │
│  - Partial observability (80m radius)                        │
│  - Dueling DQN + GRU, dynamic step budget                    │
│  - File: drqn_minimal.py, batch_runner.py                    │
└─────────────────────────────────────────────────────────────┘
```

**Why three layers?**

| Layer | Method | Responsible for |
|-------|--------|----------------|
| 1 | LLM Behavior Profiling | Who are the evacuees (age, mobility, panic tendency) |
| 2 | LLM Zone Coordinator | Where to go (zone-level shelter assignment with reasoning) |
| 3 | DRQN on OSM graph | How to get there (step-by-step navigation under uncertainty) |

## Key Features

### Evacuation Environment
- Real University of Utah campus OSM graph (walk + drive networks)
- Dynamic hazard simulation: blizzard (snow accumulation + road blocking), earthquake (initial road damage), compound
- Disaster severity grading: `light` / `moderate` / `severe` / `extreme`
- Partial observability: each agent observes within 80m radius only
- Shelter capacity management and reassignment

### DRQN Policy
- State: 37-dimensional observation (local graph features, hazard signals, subgoal direction)
- Action: top-k neighbor selection on OSM graph (variable branching factor)
- Training: adaptive distance curriculum + progressive severity fine-tuning
- Evaluation: multi-seed batch runner, severity sweep, reachability analysis

### Baseline Policies
- `round_robin`: assigns agents to shelters in rotation
- `nearest`: assigns each agent to the closest shelter
- `drqn`: learned policy via DRQN

## Results

### DRQN vs Baselines (enterprise_baseline scenario)

| Policy | avg_reached_rate | avg_exposure_total |
|--------|-----------------|-------------------|
| round_robin | 0.2654 | 286.14 |
| nearest | 0.2909 | 246.92 |
| **drqn** | **0.9627** | **5.41** |

DRQN achieves **+262.7% reached_rate** and **-98.1% exposure** vs round_robin.

### Blizzard Severity Sweep — Before vs After Fixes

Root cause identified: agents spawned on isolated nodes (`candidates=[]`) with all neighbor edges blocked at initialization. Fixed by: (1) reachable-only spawn nodes in `batch_runner.py`, (2) `EVAC_BLOCK_INIT_PROB` calibration in `scenario_loader.py`.

| Severity | Before fixes | After fixes | Improvement |
|----------|-------------|-------------|------------|
| light    | 0.835 | 0.848 | +0.013 |
| moderate | 0.752 | 0.792 | +0.040 |
| severe   | 0.646 | 0.736 | +0.091 |
| extreme  | 0.535 | 0.724 | **+0.190** |

### Single-Agent Scaling (no capacity limit)

| Scale (ped/car) | avg_reached_rate | avg_t95_step |
|----------------|-----------------|-------------|
| 60 / 20 | 0.954 | 146.4 |
| 200 / 80 | 0.990 | 197.3 |
| 500 / 200 | 0.997 | 159.0 |

DRQN scales to 700 total agents without degradation.

### LLM-Profiled Agents vs Uniform (5-Persona, blizzard severity sweep)

| Severity | Uniform | LLM-Profiled (5) | Δ |
|----------|---------|-----------------|---|
| light    | 0.848   | 0.835           | −0.014 |
| moderate | 0.792   | 0.774           | −0.018 |
| severe   | 0.736   | 0.734           | −0.003 |
| extreme  | 0.716   | 0.712           | −0.005 |

LLM-profiled agents show ~1-2% lower reached_rate, reflecting real population heterogeneity (mobility-impaired, high-panic visitors). 20-persona sweep in progress.

## Setup

```bash
# Create virtualenv and install dependencies
python3 -m venv venv
venv/bin/pip install torch networkx osmnx shapely pandas numpy groq

# Generate LLM behavior profiles (requires Groq API key)
venv/bin/python llm_behavior_profiler.py --api-key YOUR_GROQ_KEY --output agent_profiles.json

# Train DRQN (pretrain → progressive severity fine-tuning)
./train_easy.sh
./finetune_progressive_severity.sh logs/drqn_easy_pretrain/drqn_torch_best.pt

# Run severity sweep
./run_disaster_severity_sweep.sh scenarios/enterprise_blizzard.json logs/my_sweep

# Batch comparison
venv/bin/python run_disaster_severity_sweep.py \
  --scenario scenarios/enterprise_blizzard.json \
  --drqn-checkpoint logs/drqn_progressive_severity_v3_extreme/drqn_torch_best.pt \
  --output-dir logs/my_results
```
