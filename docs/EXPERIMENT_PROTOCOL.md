# Experiment Protocol (Phase 2 Frozen)

## Objective

Generate reproducible policy comparison across fixed disaster scenarios for institutional decision support.

## Frozen Scenarios

- `scenarios/enterprise_baseline.json`
- `scenarios/enterprise_blizzard_mid.json`
- `scenarios/enterprise_earthquake.json`
- `scenarios/enterprise_compound.json`

Notes:
- `enterprise_blizzard_quick.json` is for debugging/smoke tests only.
- All official runs should use the frozen scenario list above unless explicitly version-bumped.

## Frozen Policy Set

- `round_robin`
- `nearest`
- `priority_faculty`

## Execution

Single scenario:

```bash
venv/bin/python evacuation_main.py --mode batch --scenario scenarios/enterprise_blizzard_mid.json --output-dir logs
```

Full Phase 2 batch:

```bash
venv/bin/python run_phase2.py --output-root logs/phase2
```

## Outputs

Per scenario (generated by `run_batch`):
- `<scenario>_runs.csv`
- `<scenario>_summary.json`
- `<scenario>_management_summary.txt`

Cross-scenario (generated by `run_phase2.py`):
- `phase2_policy_comparison.csv`
- `phase2_policy_comparison.json`
- `phase2_policy_comparison.md`

## Reproducibility Rules

- Use scenario-defined `base_seed` and `num_runs`.
- Do not edit model or config defaults during official runs.
- If model logic changes, increment protocol version and rerun all scenarios.

## Reporting Minimum

For each scenario:
- Best policy by `avg_reached_rate` (tie-break: lower `avg_exposure_total`)
- Improvement vs baseline (`round_robin`)
- `avg_t95_step` if available
- Fairness check using `reach_rate_gap`

## DRQN Adjustment and Training Record (2026-03-17)

### Implementation Adjustments Completed

- Switched DRQN action space from fixed `N/S/E/W` to `top-k neighbor candidates` per current OSM node.
- Added `padding + action mask`; Q argmax is restricted to valid actions only.
- Added masked Double DQN target selection (next-action selection also uses mask).
- Added sequence replay compatibility for masks (store current and next action mask in replay).
- Removed fallback-grid dependency from DRQN environment; DRQN now requires OSM graph.
- Refactored reward to KPI-aligned weighted form:
  - maximize: reached/alive
  - minimize: exposure/time
- Added configurable reward/hazard parameters to CLI and checkpoint metadata.
- Added stability presets:
  - `stable_v1`
  - `stable_v2` (easier curriculum + smoother hazard settings)
