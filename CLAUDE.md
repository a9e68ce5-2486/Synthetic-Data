## Project Overview

Campus evacuation simulation for University of Utah using a three-layer LLM + RL architecture:
- **Layer 1**: LLM behavioral profiling (Groq API, Llama 3.3 70B) → `agent_profiles.json`
- **Layer 2**: LLM zone coordinator (ReAct reasoning) → zone-to-shelter assignments
- **Layer 3**: Persona-aware DRQN navigation on OSM pedestrian graph

The active model checkpoint is `logs/drqn_llm_persona/drqn_torch_best.pt` (42-dim obs, symlink to stage4).

## DRQN Training

```bash
# 4-stage curriculum (train from scratch, ~400 eps/stage)
./scripts/finetune_progressive_severity_llm.sh "" logs/drqn_llm_persona 400

# Fine-tune from existing 42-dim checkpoint
./scripts/finetune_progressive_severity_llm.sh \
  logs/drqn_llm_persona/drqn_torch_best.pt logs/drqn_llm_persona_v2 300
```

The training script chains stages automatically: light → moderate → severe → extreme, then symlinks `drqn_torch_best.pt` at the top-level output dir to the stage 4 best checkpoint.

## Architecture: Key Data Flows

### Observation Vector (42-dim, fixed)
Built in `batch_runner.py → DRQNPolicy._obs()`:
- **[0:7]** Spatial: `(dx, dy)` to sub-goal, `(dx', dy')` to shelter, blocked-edge ratio, mean snow depth, normalized step
- **[7:12]** Persona: speed/1.5, panic, familiarity, eff_compliance, eff_obs_error
- **[12:42]** Neighbors: 6 candidates × 5 features (exists, graph progress, edge length, snow depth, blocked flag)

Panic modulates persona fields at runtime: `eff_compliance = compliance × (1 − 0.5 × panic)`, `eff_obs_error = obs_error × (1 + panic)`.

### Scenario → Config Pipeline
`scenarios/enterprise_<disaster>.json` → `scenario_loader.load_scenario()` → applies `_apply_disaster_rules()` (reads LLM presets from `scenarios/llm_severity_presets.json` if present, falls back to hardcoded tables) → overrides `config.*` via `temporary_config()` context manager.

To override population size without editing scenario files: pass `--ped-count N` to sweep scripts, which sets `scenario["config_overrides"]["EVAC_PED_COUNT"]`.

### Agent Persona Assignment
`batch_runner._assign_persona(role)` samples from `_PERSONA_WEIGHTS` (role → weighted persona list). Persona fields are read from `agent_profiles.json` (generated by `llm_behavior_profiler.py`). Population: student 60%, faculty 15%, staff 20%, visitor 5%.

### Multi-Agent Inference Loop
`batch_runner.run_batch()` creates `EvacEnv` + `DRQNPolicy`, runs N seeds. `DRQNPolicy` maintains per-agent GRU hidden state (`h_states` dict). Each step: `_obs()` → `model(obs, h)` → argmax Q → move on OSM graph.

### LLM Zone Coordinator (Layer 2)
`llm_zone_coordinator.LLMZoneCoordinator.assign()` is called once before agents move. It runs a ReAct loop (tool calls: `get_shelter_status`, `get_zone_population`, `get_road_conditions`, `get_distance_matrix`) then returns a zone→shelter mapping. Falls back to algorithmic assignment if API is unavailable.

## Important Files

| File | Role |
|------|------|
| `evac_env.py` | OSM graph construction, hazard dynamics (snow/blockage/earthquake) |
| `batch_runner.py` | Multi-agent runner, DRQNPolicy class, persona assignment, obs builder |
| `drqn_minimal.py` | TorchDRQN model (GRU + Dueling DQN), training loop, GridPOMDPEnv |
| `scenario_loader.py` | Loads JSON scenarios, applies LLM/hardcoded severity overrides to config |
| `config.py` | All simulation constants (edit here or via `config_overrides` in scenario JSON) |
| `llm_zone_coordinator.py` | Layer 2 ReAct LLM coordinator |
| `llm_behavior_profiler.py` | Layer 1 persona profile generation; run once to update `agent_profiles.json` |
| `llm_scenario_generator.py` | Generates `scenarios/llm_severity_presets.json` via LLM |
| `scripts/` | All scripts prepend `sys.path.insert(0, parent_dir)` to import root modules |

## Checkpoint Compatibility

Checkpoints store `obs_dim` in their metadata JSON (`drqn_torch_weights.json`). The current model uses **obs_dim=42**. The older pre-persona model uses obs_dim=37 — these are incompatible; do not mix checkpoint paths.
